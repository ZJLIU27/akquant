## Context

持仓管理平台的规则引擎已建立插件化框架（`RuleRegistry` + `evaluate()` 接口），目前仅有一条手动止盈止损规则。需要基于"少妇战法"交易体系实现完整的止损、止盈、卖出信号规则。

现有数据：日线 OHLCV（`data/{symbol}.parquet`，字段：open/close/high/low/volume），分时缓存（`data/intraday/`）。当前 `market` 字典传递 `latest_price`、`price_source`、`intraday_df`。

关键依赖：所有规则都需要技术指标（BBI、黄线、白线等），这些指标不在原始数据中，需要在规则评估前计算好并传入。

## Goals / Non-Goals

**Goals:**
- 建立指标计算层，在规则评估前预计算 BBI、黄线、白线、量比等指标
- 实现 7 条基于实际交易策略的规则（4 止损 + 2 止盈 + 1 卖出信号）
- 保持插件化 `evaluate(position, market, params)` 接口不变
- 每条规则处理数据缺失情况，返回 `status: "unknown"`

**Non-Goals:**
- 不实现自动交易执行（规则只检测不交易）
- 不实现通知推送
- 不实现定时调度（本期仅按需评估，调度在后续迭代中加）
- 不实现仓位管理规则（仓位分配是手动决策）
- 不修改 Rust 引擎侧风控系统
- 不在规则中实现 B1/B2/B3 三件套信号检测（这是入场信号，不是持仓管理）

## Decisions

### 1. 指标计算放在 service 层，不放在规则脚本中

**选择**: 在 `service.py`（或独立的 `indicators.py`）中预计算指标，通过 `market` 字典的 `indicators` 键传递给规则。

**理由**:
- 多条规则共享相同指标（如 BBI），避免重复计算
- 规则脚本保持简单，只做阈值比较和状态判断
- 指标计算集中管理，便于测试和维护

**传递结构**:
```python
market = {
    "latest_price": ...,
    "price_source": ...,
    "intraday_df": ...,
    "daily_df": df,  # 新增：最近 N 日日线数据
    "indicators": {  # 新增：预计算指标
        "bbi": 11.35,
        "bbi_prev": 11.40,
        "yellow_line": 11.20,
        "white_line": 10.80,
        "volume_ratio": 1.5,
        "avg_volume_20d": 80000000,
    },
}
```

### 2. BBI 计算使用标准定义

BBI = (MA3 + MA6 + MA12 + MA24) / 4

使用日线 close 价格计算。需要至少 24 个交易日数据才能计算完整 BBI。

### 3. 黄线和白线的参数化

**选择**: 黄线和白线使用可配置的均线周期，通过 `registry.yaml` 的 params_schema 暴露给用户。

- 黄线（短期趋势线）: 默认使用 MA10 或 MA13（可在 params 中配置）
- 白线（长期趋势线/牵牛绳）: 默认使用 MA20 或 MA30（可在 params 中配置）

**理由**: 不同用户的均线参数可能不同，参数化比硬编码更灵活。

### 4. N型结构检测

N型结构定义：价格形成"低-高-低"（或"高-低-高"）的N字形态。在止损规则中，N型前低是指最近的波段低点。

**实现**: 在指标计算层中，检测最近 N 日内的局部最低点作为"N型前低"。使用简单的局部极值检测：某个 low 值同时小于前 M 天和后 M 天的 low 值。

### 5. 横盘三天判断

**定义**: 买入后连续三个交易日，收盘价变动幅度均不超过 ±1.5%。

**实现**: 规则从 `position.transactions` 中获取买入日期，从 `market.daily_df` 中取买入后 3 天数据，判断每日涨跌幅是否在阈值内。

### 6. 止盈放飞（两根中大阳线）判断

**定义**: BBI 线上方出现两根中大阳线。中大阳线 = 阳线（close > open）且涨幅 > 3.25%。

**实现**: 从 `market.daily_df` 中遍历最近的K线，统计 BBI 线上方连续出现的中大阳线数量。

### 7. 四分之三阴量线检测

**定义**: 突破（创新高）后，出现下跌日（close < open）且成交量 >= 突破日成交量的 75%。

**实现**: 指标计算层识别最近一次创新高日及其成交量，规则检测后续是否出现符合条件的阴量线。

### 8. S1 卖出信号（放量大阴线）检测

**定义**: 当日形成波段最高点 + 收大阴线（close < open，跌幅较大）+ 成交量显著放大（超过近期均量 2 倍）。

**实现**: 检查最新一根K线是否同时满足：创新高、收阴线、放量。

## Risks / Trade-offs

- **[数据依赖] 日线数据不足**: 新股或数据缺失时无法计算指标 → 所有规则必须处理 `indicators` 为空或数据不足的情况，返回 `status: "unknown"`
- **[准确性] N型结构检测可能不准**: 简单局部极值检测可能遗漏复杂形态 → 初期使用简单算法，后续可迭代优化
- **[参数依赖] 黄线/白线周期**: 默认参数可能不适用所有股票 → 参数化设计允许用户自行调整
- **[实时性] 按需评估非实时**: 当前仅在查看持仓时评估，不会实时推送 → 后续迭代加入定时调度
